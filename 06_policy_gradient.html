The policy gradient, hands-on

One situation, three buttons, noisy rewards: every number the policy gradient touches.

Policy gradient

The world

Three actions with noisy rewards: A ≈ 1, B ≈ 3 (best), C ≈ 2. The policy doesn't know this — it only sees the reward of what it tries.

Read the update

Δlogits = α · (r − b) · (one-hot(a) − π). The sampled action's logit moves by (1 − πa); every other logit moves by −πi. The weight (r − b) sets size and sign.

Turn on "+10"

Now every weight is positive: whatever you sample gets pushed up. Then tick the baseline: bad draws turn negative and get pushed down.

What you're looking at

Each faint line is one training run (one sample per update). The thick line is the average over 20 runs. Grey = no baseline, teal = baseline b = running average of rewards.

Same direction, less noise

Both versions point the same way on average. The baseline only removes the shared "+10" that every sample carries, so each step is mostly signal. Untick "+10": the gap shrinks, because rewards are already centred.

Crank α up

Without a baseline, big steps on noisy gradients send some runs to the wrong action and they get stuck. This is why the notebook can use lr = 2e-2 only because of its baseline.

A rare good action

Start with the policy 91% sure of A (reward ≈ 2). The best action B (≈ 3) is tried only 4.5% of the time. Baseline on in both runs.

With the log: ∇log π = ∇π / π

When B is finally sampled, its push is divided by its tiny probability — a big correction. B takes over.

Without the ÷π: ∇π

The push is multiplied by πB ≈ 0.045: rare actions barely move, even when they're great. And the common action keeps collecting pushes just for being common.

Why it's the right thing

∇π is the gradient of the probability. Averaged over how often you sample each action (π), dividing by π is exactly what makes the estimate unbiased: 𝔼a∼π[∇log π · r] = Σa ∇π(a)·r(a) = ∇J.

Same mean, narrower spread

Rewards before step t can't depend on at, so on average they contribute 0 — but in any one episode they add random noise. Reward-to-go drops them. Pick t = 9: the full return is almost all noise for the last action.
