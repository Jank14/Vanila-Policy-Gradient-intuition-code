Shapes and dims, for coding the notebook

Most VPG bugs are a dim in the wrong place. Each tab is one tensor move from the notebook, on small numbers you can see. E = num_envs, T = num_steps.

What add_step stores

Every step appends one tensor of shape (E,) — one value per env — to a list. After T steps the list has T of them.

get()

t.stack(list, dim=1) puts time along columns: (E, T), one row per env. dim=0 gives (T, E): rows and columns swapped, and every later function reads the wrong axis.

get_batches()

t.split(x, batch_size, dim=0) cuts along envs, so each batch keeps whole rows — whole games stay together.

The four lines

log_probs = F.log_softmax(logits, dim=-1)   # (E, 2)
actions = t.multinomial(log_probs.exp(), 1).squeeze(-1)  # (E,)
lp = log_probs.gather(-1, actions.unsqueeze(-1))  # (E, 1)
lp = lp.squeeze(-1)                          # (E,)

Why unsqueeze?

gather needs the index to have the same number of dims as the source. actions is (E,), the source is (E, 2), so make it (E, 1) first — then squeeze the result back to (E,).

compute_logprobs

Same move on (E, T, 2) with actions (E, T): unsqueeze to (E, T, 1), gather on dim −1, squeeze back to (E, T).

The notebook's baseline

returns.mean(dim=0, keepdim=True): one number per timestep, averaged over the envs → shape (1, T). Subtracting broadcasts it down every row.

Why per timestep?

Early steps have big reward-to-go, late steps small. Comparing each cell with other envs at the same t is "compared with usual, here and now".

keepdim

Without it you get shape (T,). It still broadcasts here, but (E,) from dim=1 would not line up — keepdim makes the intent explicit.

Type your own test case. Compare with what your compute_returns prints for the same row.

The loop

G = zeros(E)
for i in reversed(range(T)):
    G = rewards[:, i] + gamma * G * (~dones[:, i])
    returns[:, i] = G

Read the table right to left

Each G is this step's reward plus γ × the G to its right — unless this step is done, which blocks the future (the next cell belongs to a new game).

Last column

The window ends: G starts from 0 even if the game was still running (truncation by the rollout).

How to use it

Add print(x.shape) after each line of your compute_loss and compare with this table. The first mismatch is your bug.

The one scalar

Everything is (E, T) until the final .mean(), which gives a 0-dim tensor: joy. If joy is not a scalar, a mean is missing.
